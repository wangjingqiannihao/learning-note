# curl 指定 IP 和网口访问差异

## 结论

`curl --interface 源IP 目标地址:端口` 能通，但 `curl --interface 网口名 目标地址:端口` 不通，通常不是目标服务本身的问题，而是本机出方向网络选择不一致导致的。指定源 IP 时，连接的源地址是明确的；指定网口名时，只是把连接绑定到某个网络设备，内核仍可能选择不符合预期的源 IP、路由表、协议族或回包路径。

因此，排查时不要只看网口是否存在，也要同时确认源 IP、路由、策略路由、IPv4/IPv6 选择和反向路径检查是否一致。生产排障中，如果目标是验证某个源地址的连通性，通常更推荐直接使用 `--interface 源IP`。


## 两种写法的关键区别

`--interface 源IP` 的重点是指定连接使用哪个本地源地址。只要这个 IP 存在于本机，并且系统能够为这个源 IP 找到可达目标地址的路由，连接就有机会成功。

`--interface 网口名` 的重点是指定连接绑定在哪个网络设备上。它并不等价于指定这个网口上的某个具体 IP。如果网口上配置了多个 IP，或者系统路由策略依赖源 IP，绑定网口后仍可能选到错误的源地址，最终导致访问失败。

## 常见原因

| 原因 | 说明 | 典型表现 | 处理建议 |
|---|---|---|---|
| 网口上存在多个 IP | 指定源 IP 时，源地址已经明确；指定网口名时，系统可能选择该网口上的另一个 IP。 | `--interface 源IP` 能通，`--interface 网口名` 不通，或者目标侧看到的来源 IP 不符合预期。 | 优先使用 `--interface 源IP`；如果必须指定网口，需要确认该网口上的默认源地址是否符合预期。 |
| 目标地址实际路由不走指定网口 | Linux 的路由选择主要由路由表和策略路由决定，绑定网口不代表目标路由一定从该网口出去。 | 连接失败、超时，或者回包路径异常。 | 确认访问目标地址时系统实际选择的出接口，必要时调整路由。 |
| 策略路由依赖源 IP | 多网卡环境中可能存在基于源 IP 的 `ip rule`。只有指定某个源 IP 时，才会命中特定路由表。 | 指定源 IP 能命中正确路由表；只指定网口名时，可能命中默认路由表或错误路由表。 | 检查策略路由规则，确保源 IP、路由表和出接口匹配。 |
| IPv4 和 IPv6 选择不同 | 目标地址是域名时，curl 可能优先尝试 IPv6，而指定网口可能没有可用 IPv6 地址或 IPv6 路由。 | 指定 IPv4 源地址能通，但指定网口名访问域名失败。 | 分别使用 `curl -4` 和 `curl -6` 验证，明确问题是否来自协议族选择。 |
| 反向路径检查影响 | Linux 的 `rp_filter` 会检查回包路径是否合理。多网卡、多路由表、非对称路由场景下可能丢包。 | 出包看似正常，但连接无响应或超时。 | 检查对应网口和全局的 `rp_filter` 配置，并结合实际路由判断是否存在非对称路径。 |

## 推荐使用方式

如果目标是验证某个源地址到目标服务的连通性，优先使用下面这种方式：

```bash
# 推荐：明确指定源 IP，减少多网卡和多 IP 环境下的不确定性
curl --interface 源IP http://目标地址:端口
```

如果必须绑定网口名，需要先确认该网口、源 IP、路由表和策略路由是一致的：

```bash
# 先确认目标是否真的会从这个网口出去
ip route get 目标IP

# 再确认期望的源 IP 是否在这个网口上
ip addr show dev 网口名
```
